# v14: оценка через LLM, обучение слова через LLM, легенда групп

## Что изменено по запросу
1. **Оценка через LLM вместо совпадения слов.** `nets/judge.py`: судья LLM оценивает
   мысль сети по эталону (подтверждённый ответ) шкалой 0–10. Без ответа LLM откат на
   совпадение слов. Используется в адаптации (`/good`, `/teach`) и в дистилляции.
2. **Правый клик по слову → «обучить через LLM».** LLM подробно объясняет слово, текст
   показывается в чате. Сеть создаёт исходящие связи от слова и от слов объяснения,
   затем рекуррентно воссоздаёт слои: L1 — слова ответа, L2, L3 — от предыдущего слоя.
   Вес убывает с глубиной.
3. **Дистилляция знаний из LLM в сети.** Учитель строится из объяснения, его
   распределение переходов переносится в ансамбль на копии; коммит по качеству.
4. **Все группы нейронов видны.** Клавиша F3 открывает легенду: все группы (включая
   одиночные) с цветом, размером и словами. Раньше подписи были только у групп из двух и
   более нейронов.

## Исправленные по ходу ошибки
- Адаптация после `/good` в первой версии запускалась синхронно и оценивала по словам.
  Переведена на LLM-драйвер; без LLM откатывается на совпадение слов.
- Бюджет LLM-адаптации был слишком большим (около 40 запросов). Уменьшен до ~12.
- Драйвер задач учитывает перебивание запроса ответом в чат: `is_current` и повторная
  отправка (закладывалось заранее, покрыто тестом `test_resubmits_when_superseded`).

## Ограничения (честно)
- Качество объяснения и оценок зависит от модели. Слабая модель даст слабый учитель.
- Оценка судьи — число от модели, не строгая метрика. Для строгой оценки нужны эталоны.
- Адаптация и дистилляция проходят через песочницу, но коммит по LLM-оценке на малой
  выборке шумный: при 3–4 парах решение может быть случайным.
- Если во время обучения сменили мозг (`/reset`, `/load`), план применится к новому.
- Легенда показывает группы, но не подсвечивает новые связи на сцене.
