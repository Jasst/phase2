# Озвучка ответов: Silero TTS

Русский голос работает локально: CPU, интернет не нужен после загрузки модели.

## Установка

1. Зависимости (отдельно от основного проекта, torch большой). Ставить нужно **в `.venv`** —
   именно его активирует `run_server.bat`. torch в глобальном Python серверу не виден:
   ```
   .venv\Scripts\python.exe -m pip install -r requirements-tts.txt
   ```
   Для CPU можно поставить лёгкую сборку torch с индекса PyTorch (команда в файле).
   Проверка: `.venv\Scripts\python.exe -c "import torch; print(torch.__version__)"`.
   Если в `/api/tts/status` в `error` написано `No module named 'torch'` — зависимость попала
   не в то окружение; после установки нажмите «Озвучить» ещё раз (старая ошибка сбросится)
   либо перезапустите сервер.

2. Модель. Один из двух способов:
   - вручную: скачать `https://models.silero.ai/models/tts/ru/v4_ru.pt` и положить в `data_unified/tts/v4_ru.pt`.
     В PowerShell из корня проекта:
     ```
     New-Item -ItemType Directory -Force data_unified\tts | Out-Null
     Invoke-WebRequest -Uri https://models.silero.ai/models/tts/ru/v4_ru.pt -OutFile data_unified\tts\v4_ru.pt
     ```
     Путь по умолчанию — `data_unified/tts/`, а не `data/tts/`. Если держите модель в другом месте,
     укажите его в `SILERO_MODEL_PATH`;
   - автоматически: `SILERO_AUTODOWNLOAD=1`, файл загрузится при первом запросе озвучки.

3. В `.env`:
   ```
   SILERO_ENABLED=1
   # доступные голоса: aidar, baya, kseniya, xenia, eugene
   # это голос по умолчанию; пользователь может выбрать другой в интерфейсе
    SILERO_SPEAKER=xenia
   # cuda — только если torch собран с CUDA и хватает видеопамяти
    SILERO_DEVICE=cpu
   # пусто = data_unified/tts/v4_ru.pt
    SILERO_MODEL_PATH=
   SILERO_AUTODOWNLOAD=0
   ```

Комментарии в `.env` пишите на отдельной строке: ` # ...` парсер отрезает, но `value#comment`
без пробела перед `#` считается частью значения.

## Как работает

- Во время генерации ответа у сообщения есть кнопка «Озвучивать по ходу генерации»: готовые фразы
  проигрываются сразу, остальные добавляются по мере появления.

- Кнопка «Озвучить» в меню ответа отправляет текст на сервер. Сервер убирает код, таблицы,
  ссылки и служебные пометки, режет ответ на фразы.
- Фразы проигрываются по очереди; следующая скачивается, пока играет текущая.
- Если модель не загружена или сервер озвучки недоступен, интерфейс предупреждает и переходит
  на голос браузера.
- Маршруты: `GET /api/tts/status` (в ответе — список `voices` с подписями и фразами-примерами),
  `POST /api/tts/segments`, `POST /api/tts` (возвращает WAV; поле `speaker` в теле задаёт голос
  для этого запроса, не меняя голос сервера по умолчанию).

## Выбор голоса и сохранение настроек

- В строке ввода рядом с «Рассуждениями» и «Интернетом» есть кнопка «Голос». В выпадающем списке
  перечислены все голоса Silero с описанием тембра; кнопка **▶** рядом с голосом проигрывает
  короткий пример (фразы заданы в `pulsenet/tts.py`, `VOICE_INFO`).
- Выбранный голос передаётся с каждым запросом озвучки, поэтому он не «протекает» в другие
  сессии: `SILERO_SPEAKER` из `.env` — только значение по умолчанию, пока пользователь ничего
  не выбрал.
- Все настройки интерфейса (голос, модель, переключатели ввода, размер текста, компактный режим,
  автоскролл, Enter) сохраняются в двух местах: мгновенно в `localStorage` и с небольшой задержкой
  на сервере в `data/settings.sqlite` (таблица `user_settings`, ключ — uid). API: `GET /api/settings`,
  `PUT /api/settings`. При старте и при обновлении статуса более свежая серверная копия
  подтягивается в интерфейс. Благодаря этому выбор не сбрасывается после перезапуска сервера
  и синхронизируется между устройствами одного аккаунта; `localStorage` работает как офлайн-кеш.

## Замечания

- Озвучка идёт на CPU параллельно с ответом модели. На слабой машине во время длинного ответа
  может замедлиться генерация; в этом случае озвучивайте после ответа.
- Голос звучит лучше браузерного, но тембр и интонация зависят от версии модели.
