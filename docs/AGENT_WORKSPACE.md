# Рабочее пространство агента (data_unified)

Агент чата может учиться на опыте: сохранять повторяемые приёмы как навыки, вести заметки
(в том числе с картинками из `image_generate`) и помнить собственные самонаблюдения. Всё это
лежит в каталоге `data_unified` — том же, что использует unified MCP. Это обычные файлы:
их можно открыть, поправить или удалить руками.

```
data_unified/
  AGENTS.md                    правила для чат-агента (необязательно)
  skills/<name>/SKILL.md       навык: frontmatter (name, description) + инструкция
  skills/<name>/.history/      прежние версии навыка (последние 10)
  notes/<slug>.md              заметка; kind: note | self
```

Формат `SKILL.md` совпадает с навыками opencode (`.opencode/skills/*/SKILL.md`), поэтому
навык можно переложить из одного места в другое без правок.

## Что делает агент

- В системный промпт попадают: правила `AGENTS.md`, список навыков (имя и описание), последние
  самонаблюдения (`kind: self`) и полный текст навыка, если он подходит к запросу.
- Инструменты: `skill_list`, `skill_read`, `skill_write`, `skill_patch`, `note_write`,
  `note_append`, `note_read`, `note_list`, `todo_write` (план задачи из нескольких шагов).
- `note_write` / `note_append` принимают `image_url`; значение `"last"` вставляет картинку,
  созданную в этом же ходе.

## Ограничения записи

- Имя навыка — slug из латиницы, цифр и дефиса. Имена заметок могут быть на любом языке.
- Тело навыка до 12 000 символов, заметки до 8 000.
- Секреты (ключи `sk-…`, `password=`, `Bearer …`) не сохраняются.
- Картинка — только `http(s)://` или путь от `/`.
- Выключить запись навыков: `AGENT_SKILLS_WRITE=0`.

## Правила пользователя

Скопируйте `docs/CHAT_AGENTS.example.md` в `data_unified/AGENTS.md` и отредактируйте.
Файл читается при каждом ходе чата.

## Параллельные вызовы и субагенты

- За один шаг модель может вызвать до `AGENT_CALLS_PER_STEP` инструментов. Независимые
  вызовы (поиск, чтение, картинка) выполняются параллельно, результаты возвращаются в порядке вызовов.
- Инструменты записи (`skill_write`, `skill_patch`, `note_write`, `note_append`, `todo_write`,
  `memory_remember`) всегда идут по очереди.
- `subagent(task, tools?)` запускает субагента: отдельный короткий цикл с тем же LLM и
  инструментами текущего хода, кроме записи и самого `subagent`. Его вызовы видны в трассе
  (вложенные карточки). Несколько `subagent` в одном шаге выполняются одновременно;
  запросы к модели идут по очереди, если `AGENT_LLM_PARALLEL=1`.

## Выбор модели

Модель меняется только по явному выбору пользователя в строке ввода (`model` в запросе) или
значению `LMSTUDIO_MODEL` / `LLAMACPP_DEFAULT_MODEL` в `.env`. Порядок разрешения:
`model → активная модель последнего чата → default из настроек`.

Список моделей, статус и запись в память не опрашивают LM Studio «на предмет первой загруженной
модели» и не перезаписывают выбор: открытие выпадающего списка или фоновая индексация больше не
меняют модель в чате. Запись фактов идёт той же моделью, что и текущий чат; если модель указана
явно для одной операции, она действует только на неё.

Если модель не выбрана ни в интерфейсе, ни в `.env`, запрос завершается явной ошибкой
«модель не выбрана» — бэкенд больше не подставляет первую попавшуюся загруженную модель и не
записывает заглушку `(внешний сервер)` в активную модель. Для llama.cpp внешний сервер, поднятый
другим процессом, больше не перехватывает выбор: без явной модели он не назначается сам.

## Трасса работы агента

В блоке «Ход работы» под ответом показываются отдельные карточки шагов: начало запроса к модели,
итоги со списком вызовов и финальная заметка с причиной останова. У каждой карточки есть бейдж
фазы, бюджет (`шаг 2/6 · вызовов 3/20`), длительность, аргументы вызовов, размер результата
и пометка «обрезано». Для незавершённого шага показывается индикатор выполнения.

- События `step` приходят в том же SSE-потоке, что `token`, `tool` и `trace`, и работают и при
  переподключении к уже идущему ходу (`/api/chat/stream`).
- Полная лента шагов сохраняется вместе с сообщением в серверных чатах (`steps`), поэтому
  трасса не теряется при обновлении страницы и синхронизации между устройствами.
- Лимит шагов/вызовов проверяется **до** запроса к модели. После последнего раунда инструментов
  модель делает ещё один вызов без инструментов и даёт итоговый текст — ответ не обрывается
  на невыполненном `<tool_call>`.
- `AGENT_MAX_TOKENS` задаёт лимит генерации шага. Если модель собирает JSON вызова, но
  токенов не хватает, увеличьте это значение (по умолчанию 2048).
- Результаты инструментов усекаются до `TOOL_RESULT_CONTEXT_CHARS` так, чтобы JSON оставался
  валидным: модель не тратит раунд на разбор битого ответа.

## Цепочка идентичности

Подтверждённые звенья `users/<uid>/identity.json` попадают в системный промпт только для
своего пользователя. Кандидаты (ожидающие подтверждения) не попадают.

## Устойчивость (v4)

- Ход чата занимает модель: индексация ждёт окончания хода и пишет пакетами (`INDEX_MODE`,
  `INDEX_DEBOUNCE_SECONDS`, `INDEX_BATCH_MAX`). Приветствия и короткие реплики не индексируются.
- Сбой соединения с LLM до первого видимого токена повторяется дважды. Если модель так и не ответила,
  ход завершается текстом «Модель не ответила» и трассой `llm_error`, а не ошибкой.
- Ошибка одного параллельного инструмента становится результатом для модели; ход продолжается.
- Субагент получает вопрос пользователя как контекст и поле `context` из вызова.
- После сбоя сервера памяти ход не ждёт его `MCP_COOLDOWN_SECONDS`.
