# ТРИПЛЕКСИЯ как внешняя память для opencode (и других MCP-клиентов)

## 1. Запуск сервера

1. В `.env` задайте токен (один раз):

       python -c "import secrets; print(secrets.token_urlsafe(32))"

   Вставьте результат в `PULSENET_MCP_TOKEN=`. Без токена `/mcp` отвечает 503.
2. Запустите `run_server.bat` (или `python -m pulsenet serve`). Адрес: `http://127.0.0.1:8000`.
3. Проверка, что MCP жив:

       curl -s -X POST http://127.0.0.1:8000/mcp/ \
         -H "Authorization: Bearer <TOKEN>" -H "Content-Type: application/json" \
         -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

   В ответе должны быть 13 инструментов `triplex_*`.

## 2. Подключение opencode

Единый MCP-сервер проекта: `pulsenet-unified` → `http://127.0.0.1:8010/mcp`
(инструменты: `triplex_*` — память; `web_*` — интернет; веб-поиск через SearXNG).

В корне проекта (или в `~/.config/opencode/opencode.json`) создайте `opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "pulsenet-unified": {
      "type": "remote",
      "url": "http://127.0.0.1:8010/mcp",
      "headers": {
        "Authorization": "Bearer <PULSENET_MCP_TOKEN>"
      },
      "enabled": true
    }
  }
}
```

Токен берётся из переменной окружения `PULSENET_MCP_TOKEN` (не храните его в файле).
Перезапустите opencode и проверьте, что инструменты `triplex_*` и `web_*` появились в списке.

Для клиента за nginx вместо адреса 127.0.0.1 используйте `https://<домен>/mcp/`
и добавьте домен в `PULSENET_MCP_HOSTS` в `.env`. nginx проксирует `/mcp` на backend :8010 (unified).

## 3. Как заставить модель пользоваться памятью

MCP только даёт инструменты. Модель будет ими пользоваться, если в инструкциях проекта
прописан протокол. Создайте `AGENTS.md` в корне репозитория (opencode читает его как
системные инструкции проекта):

```markdown
# Память ТРИПЛЕКСИЯ (MCP: triplex)

Перед нетривиальной задачей:
1. Вызови triplex_search с формулировкой задачи. Если в ответе есть факты или context,
   учитывай их и явно скажи, что опираешься на память.
2. Если факт в памяти противоречит тому, что видишь в коде, доверяй коду
   и вызови triplex_supersede или triplex_retract для старого факта.

После решения (архитектура, выбор библиотеки, найденный баг, правило проекта):
1. Сохрани исходный текст решения через triplex_ingest (role=assistant).
2. Для каждого устойчивого факта вызови triplex_assert с source={doc_id, span}
   из ответа ingest. Факт без источника не записывается (инвариант I1).

Не сохраняй секреты, токены и пароли. Не сохраняй догадки: только подтверждённое.
```

## 4. Как проверить, что память работает

- В веб-интерфейсе откройте «Память» (кнопка в боковой панели или инструмент «Память»).
  Там список фактов с источниками, кнопки подтвердить / опровергнуть / отозвать, поиск
  и ввод текста.
- Через MCP: вызовите `triplex_stats` и `triplex_check` (должен вернуться `ok: true`).
- Быстрый тест: в opencode скажите «запомни: в этом проекте используем Python 3.12»,
  затем в новой сессии спросите «какой Python в проекте» и посмотрите, вызвала ли модель
  `triplex_search`.

## 5. Что уже умеет, что ещё нет

Есть: сохранение и поиск с источниками, отзыв без потери истории, конфликты для
функциональных отношений, затухание старых фактов, лексический поиск с учётом русских
окончаний (с этой версии), сухой прогон «сна».

Нет (честно): обучение LoRA (веха M6) пока не запускается; выделение логических цепочек
сводится к обходу связей в поиске, а не к отдельному рассуждающему слою; качество поиска
по смыслу сильно зависит от модели эмбеддингов (с офлайн-хешем опирайтесь на лексику,
для нормального поиска подключите bge-m3 через LM Studio, см. `.env.example`).
Память повышает качество ответов за счёт контекста, но сама по себе не делает
локальную модель умнее: для этого нужны фиксация решений в памяти и, позже, консолидация.
