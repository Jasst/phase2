# nets — взаимодействующие нейросети

Все сети проекта живут в этой папке. Здесь же лежат матрицы перерасчёта,
чтобы было видно, как одна мысль переходит в другую сеть.

## Что внутри

| Файл | Роль |
|---|---|
| `core.py` | Одна сеть: узлы-слова, веса связей, температурные переходы, асинхронный проход в случайном порядке, мутации, дистилляция |
| `chain.py` | Цепочка сетей: выход сети 1 → вход сети 2 → … → финальная мысль. Динамическое число раундов |
| `transfer.py` | Матрица перерасчёта M_AB между двумя сетями и её дамп в `_matrices/` |
| `cluster.py` | Мутации ансамбля, кластеризация по откликам, (1+λ) эволюция |
| `sandbox.py` | Изолированная адаптация: копия, проверка на отложенной выборке, коммит при росте качества |
| `build.py` | Сеть из текстового файла (один файл — один слой знаний) |
| `store.py` | Сохранение ансамбля в `_store/` (JSON на сеть) |
| `demo.py` | Запуск на текстах проекта: `python -m nets.demo "вопрос"` |
| `tests/test_nets.py` | Тесты: `python -m unittest nets.tests.test_nets -v` |

## Как работает

**Температура.** Переход из узла i в узел j имеет вероятность
`p(j|i) ∝ exp((log(1+w_ij) − HUB·log(1+deg_j)) / T)`.
- малое T — жадный выбор самой сильной связи;
- большое T — мысль разнообразнее;
- при обучении T задаёт, охотно ли создаются новые связи: `P(создать) = 1 − exp(−T·gain)`.

**Случайный порядок нейронов.** Один проход обходит узлы в случайном порядке.
Масса, переданная узлу раньше в этом же проходе, уже видна следующим узлам,
поэтому порядок влияет на результат. Генератор порядка — `seed` цепочки:
один и тот же вход при одном seed даёт один и тот же путь.

**Гашение хабов.** Слова, связанные со всем подряд, штрафуются через
in-degree. Это не даёт словам вроде «всего» доминировать в каждой мысли.

**Цепочка.** Раунд: вход проходит сети 1…N по порядку. Каждая сеть получает
выход предыдущей и накопленную сумму выходов всех предыдущих (общее число).
Мысль — то новое, что добавили сети к вопросу (эхо входа исключается).
Раунды повторяются, пока мысль не стабилизируется (косинус между раундами
≥ 1 − eps). Число раундов динамическое: энтропийная (размазанная) мысль
получает больше раундов, но не больше `max_rounds` и не дольше `time_budget`.

**Матрица перерасчёта.** Сети связаны через общие узлы (слова, которые есть
в обеих). Путь массы из A в B: `i → k` (переход в A), `k` — общий узел-мост,
`k → j` (переход в B). Итог:

    M_AB[i][j] = Σ_k P_A(k | i) · P_B(j | k),   k ∈ nodes(A) ∩ nodes(B)

Строка i — куда уходит масса слова i из A при переходе в B. Сумма строки ≤ 1.
Файлы: `_matrices/A__B_T1.00.json` (полностью) и `.txt` (топ связей по строкам).
Пример читаемого дампа — `_matrices/corpus__tech_T1.00.txt`.

Матрица — диагностика. Цепочка идёт теми же переходами пошагово, но матрица
показывает, какая мысль из одной сети во что превращается в другой.

**Мутации и кластеры.** Мутант получает часть ослабленных/удалённых связей,
log-normal шум на веса и новые случайные связи. Ансамбль из мутантов
кластеризуется по откликам на пробные вопросы (Jaccard по топ-словам):
сети с похожим откликом попадают в один кластер.

**Изолированная адаптация.** `Sandbox.adapt()` работает на глубокой копии:
обучает копию на train-парах, эволюционирует, дистиллирует от лучшей сети
к остальным (мягкие цели учителя при температуре T_d), проверяет на val-парах,
которых копия не видела. В живой ансамбль результат попадает только если
качество выросло больше `margin`. Отчёт пишется в `_sandbox/last_adapt.json`.

## Ограничения (честно)

- Это графовые ассоциативные сети, а не трансформеры. Обучения градиентным
  спуском нет: веса меняются по совместной встрече, мутации и дистилляции.
- Качество мыслей ограничено текстами. Слово, которого нет в файлах, даёт
  пустую мысль: сеть не знает ответа и не выдумывает его.
- Метрика качества — recall по словам, а не смысл. Для оценки ответов нужна
  человеческая разметка или LM.
- Не подключено к `brain_chat.py`. Точка подключения: `Answerer.think()` может
  вызывать `Chain.run()` и брать `thought` как затравку. Это отдельный шаг.

## Менеджер и обучение по наградам (v13)

`NetsManager` (`manager.py`) связывает ансамбль с приложением:

- **Открытие.** `NetsManager.open()` загружает `_store/`. Если хранилища нет,
  строит по одной сети на файл из `corpus.txt`, `tech.txt`, `nature.txt`, `daily.txt`.
- **Мысль.** `think(вопрос)` запускает цепочку. Трасса пишется в `_logs/last_chain.txt`
  (команда `/chain`), история вопросов в `_logs/chain_history.jsonl` (до 500 строк).
- **Обучение.** `/good` и `/teach` вызывают `feedback(вопрос, ответ, вес)`. Пара
  дописывается в `_store/feedback.jsonl` без предела (опыт растёт). Граф сразу
  не меняется. После `adapt_every` пар (по умолчанию 4) запускается `Sandbox.adapt()`:
  копия обучается на 3/4 пар, проверяется на остальных, коммит при росте качества.
- **Ограниченный граф.** После принятой адаптации у каждого узла остаётся не больше
  `MAX_OUT = 60` исходящих связей (слабые удаляются). Опыт растёт, активный граф — нет.
- **Диагностика.** `/nets` — состояние сетей, очереди адаптаций и последний отчёт.

## Как цепочка попадает в ответ (reasoning.py)

`Answerer.think()` получает `nets`. Если вопрос содержит слова, знакомые графу,
цепочка даёт мысль с меткой `chain`. Она становится лучшим кандидатом режима
«вся сеть», если её оценка выше мысли графа. Оценка считается той же формулой
(поддержка, устойчивость, длина). Бандит стратегий (`rl_policy`) учится дальше
на оценках пользователя, так что вклад цепочки проверяется наградами.

| Путь | Что там |

## Оценка через LLM-судью (v14)

Оценка качества больше не считается только по совпадению слов. `judge.py` просит LLM
оценить мысль сети по эталону (подтверждённый ответ) от 0 до 10. Если LLM не ответила
или ответ без числа, для этого примера берётся совпадение слов, поэтому система
работает и без LLM. Оценка и адаптация оформлены как генераторы (`cluster.py`,
`sandbox.py`, `manager.py`): каждый запрос к судье отдаётся главному циклу, UI не
ждёт модель.

Бюджет адаптации в LLM-режиме: 1 поколение, 3 мутанта, около десятка оценок.

## Обучение слова через LLM (v14, `teach.py`)

Правый клик по слову → «обучить через LLM»:

1. LLM объясняет слово: где и как используется, какие слова рядом. Текст показывается в чате.
2. `teacher_from_text` строит сеть-учителя: слово соединяется с каждым словом ответа,
   слова внутри предложений связываются по порядку.
3. `build_layers` воссоздаёт слои рекуррентно: L1 — слова ответа, отобранные учителем
   по активации от слова; L2, L3 — проход учителя от предыдущего слоя. Вес связей
   убывает с глубиной (`DECAY`).
4. `apply_plan` записывает слои в граф через `brain.associate` (исходящие связи от слова
   и от каждого слоя). Сети ансамбля получают дистилляцию распределения учителя
   на копии, коммит только если качество на последних подтверждённых парах не упало.

Драйвер `llm_tasks.py` выполняет задачи в главном цикле без потоков: один запрос к LM
за раз, задачи ждут, пока LM занята ответом в чат, и перезапускаются, если ответ в чат
перебил их запрос.
