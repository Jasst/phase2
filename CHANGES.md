# brain_project — что изменено

## Исправления
- `train_start.py`: импорт `phase2.brain_chat` не работал со структурой архива. Теперь сначала
  пробуется `from brain_chat import ...`, и только потом старый путь `phase2/`.
- `lm_backend.py`: журнал оценок `dialog_log.jsonl` писал буквальную строку `\\n` вместо перевода
  строки, из-за чего записи склеивались в одну строку JSON. Исправлено.

## Когнитивные улучшения
- **Рабочая память / тема разговора** (`mind.py`). Сеть помнит, о чём идёт разговор: сглаженный
  контекст последних вопросов (`topic`) смещает выбор слов в обоих полушариях. Тема угасает
  медленно в фоновом мышлении. Служебные слова из темы отфильтрованы.
- **Эпизодическая память** (`episodes.py`, файл `episodes.json`). Подтверждённые пары
  «вопрос → ответ» сохраняются при `/teach` и `/good` и ищутся по TF-IDF косинусу.
  - Сходство ≥ 0.7 и режим без LM: ответ берётся из памяти.
  - Сходство ≥ 0.3 и есть LM: прошлый ответ передаётся модели как проверенная подсказка.
  - `/bad` удаляет эпизод. `/sleep` повторяет эпизоды через граф.
- **Самопроверка** (`mind.support`). Для каждого ответа LM считается, насколько он опирается
  на окрестность вопроса в графе. Значение выводится в `/mind`.

## Визуализация
- Индикатор активного полушария (левое/правое) с пульсирующим ореолом.
- График согласованности полей, растягивается по мере накопления данных.
- Наведение на нейрон: подсказка (слово, слой, число связей, группа) и подсветка его связей и соседей.
- Подписи слов: при малой сети видны все, при большой только у активных, наведённых и соседних.
- В строке состояния счётчик эпизодов.

## Работа с GGUF / LM
- **Потоковая генерация** (`lm_backend.py`). Текст появляется по мере генерации, и для
  llama-cpp-python, и для LM Studio (SSE). Блоки `<think>` вырезаются на лету.
- **Отмена устаревших запросов.** Новый вопрос прерывает генерацию предыдущего на ближайшем
  фрагменте, а результат отменённого запроса не публикуется.
- **Эпизоды в промпте.** Проверенные прошлые ответы передаются модели отдельной строкой,
  с пометкой, что им можно доверять больше ассоциаций.
- **Скорость.** `/mind` показывает токенов в секунду.
- **Настройки** (новые переменные окружения):
  - `BRAIN_LM_THREADS`: потоки CPU для llama.cpp.
  - `BRAIN_LM_CHAT_FORMAT`: шаблон чата, если авто-определение из GGUF не подходит (например `chatml`).
  - `repeat_penalty=1.1` для llama.cpp.

## Новые команды
- `/recall текст`: показать три ближайших эпизода из памяти с их сходством.
- `/mind`: тема разговора, полушарие, самопроверка, число эпизодов, скорость LM.

## Тесты
Папка `tests/`. Запуск из корня проекта:
- `python tests/test_lm.py`: журнал, потоковая генерация, отмена запросов.
- `python tests/test_sse.py`: разбор SSE для LM Studio на локальном mock-сервере.
- `python tests/test_e2e_headless.py`: полный цикл `main()` без окна, со сценарием ввода.

Тесты проверены в headless-окружении. Реальную модель GGUF и окно pygame на вашей машине
нужно проверить отдельно.

## Что стоит сделать дальше
- Словарь обрезается лимитом `MAX_NEURONS = 450`. На корпусе из `corpus/` в сеть попадает
  около 230 из ~800 слов (`train_start.py` предупреждает об этом). Если поднять лимит,
  память и время отрисовки вырастут; это решение лучше принять вам.
- В папке `mind_new.py` пустой файл. Его можно удалить.

# Версия 3: осознанный ответ

## Что изменилось в конвейере ответа (`reasoning.py`, новый)
1. **Мысль из нескольких групп.** Для вопроса строятся варианты: вся сеть и каждая из трёх
   наиболее близких групп нейронов (затравка — два слова группы). Каждый вариант даёт черновик.
2. **Рекуррентное самосогласование.** Черновик снова подаётся в сеть как контекст, пока
   совпадение с предыдущим шагом не достигнет 0.6 (до трёх шагов).
3. **Выбор мысли.** Оценка = 0.5·опора на граф + 0.3·устойчивость + 0.2·длина. Лучшая мысль
   показывается в панели «МЫСЛИ» (группа и оценка).
4. **LM пишет связный ответ** по мысли. Мысль передаётся как подсказка в системный промпт.
5. **Перепроверка и переписывание.** Ответ LM оценивается сетью (опора на граф). Затем LM
   получает свой черновик и просьбу проверить и исправить. Лучшая версия остаётся.
   Число переписываний задаётся `BRAIN_REVISE` (по умолчанию 1, 0 — отключить).
6. **Обучение.** Ответ с оценкой ≥ 0.12 обучает граф: вопрос и ответ связываются, новые слова
   становятся нейронами, цепочка ответа усиливается.

## Интерфейс
- Служебные сообщения (поток, тема, «Уверенность низкая», «Вспомнила…») убраны из чата.
  Их состояние доступно в `/mind`. Полоса «Сеть говорит» скрыта.
- Подсветка нейронов держится дольше: ~3 с вместо ~0.6 с (`HOT_NODE`, `HOT_LINK`).
- Память потока длиннее: `STREAM_LEN` 160, `RECENT_DECAY` 0.95.

## Важно
- Без LM граф отвечает набором связанных слов: понятного текста из него не получится.
  Для связного ответа нужна GGUF-модель.
- Обучение на собственных ответах LM может закреплять ошибки. Порог `LEARN_MIN` в `reasoning.py`
  и `/bad` (удаляет эпизод и ослабляет цепочку) — ваши инструменты контроля.
- Тесты: `tests/test_e2e_headless.py` (режим без LM), `tests/test_pipeline_fakelm.py`
  (конвейер с фейковой LM: проверяет мысль в запросе и переписывание), `test_lm.py`, `test_sse.py`.

# Версия 4: чистый ответ, настройки модели, связи и понятные команды

## Ответ без служебных инструкций (`lm_backend.py`)
- `strip_leaks()`: если модель повторила служебные подсказки графа («Ассоциации графовой памяти»,
  «Проверенные прошлые ответы», «Мысль сети», «Черновик», `/no_think`), предложения с ними
  удаляются из ответа. Пользователь видит только сам ответ.
- Системный промпт прямо запрещает пересказывать и цитировать подсказки.
- Ответ, оборванный лимитом времени или токенов, обрывается по последней законченной фразе.

## Настройки модели, разделённые и доступные пользователю
Команды меняют параметры на лету; значение без числа показывает текущее.
- `/ctx N` — контекст диалога в символах (история и подсказки, по умолчанию 6000).
- `/history N` — сколько прошлых обменов модель помнит (по умолчанию 3).
- `/time N` — секунд на один ответ, 0 — без лимита (по умолчанию 60).
- `/tokens N` — максимальная длина ответа в токенах (по умолчанию 220).
- Переменные окружения: `BRAIN_LM_CONTEXT_CHARS`, `BRAIN_LM_HISTORY`, `BRAIN_LM_TIME_BUDGET`, `BRAIN_LM_MAX_TOKENS`.
- Важно: `BRAIN_LM_CTX` (размер окна, заложенный в модель при загрузке) меняется только при перезапуске.
  `/ctx` ограничивает объём контекста, который реально передаётся модели, и не перезагружает её.

## Нейроны и обучение ассоциациям
- `/neurons N` — лимит нейронов на ходу (100–2000). По умолчанию 700 (было 450), либо `BRAIN_MAX_NEURONS`.
  Больше нейронов — больше нагрузка на отрисовку.
- `/assoc слово слово …` — явно связать слова между собой (повтор делает связь сильнее, группы перестраиваются).

## Интерфейс и диагностика
- `/help` — список команд по смыслу: вопрос, оценка, обучение, память, сеть, модель, состояние.
- Стартовая строка чата больше не перечисляет все команды, а указывает на `/help`.
- `/mind` показывает настройки модели и число нейронов относительно лимита.

## Тесты
- `tests/test_commands_v4.py`: команды `/help`, `/ctx`, `/time`, `/tokens`, `/history`, `/neurons`, `/assoc`,
  `/mind`; очистка служебных фрагментов; лимит времени на ответ.
- Старые тесты (`test_lm`, `test_sse`, `test_e2e_headless`, `test_pipeline_fakelm`) проходят без изменений.

## Не сделано (честно)
- Полная перерисовка pygame-интерфейса не выполнена: изменения касаются текста, команд и диагностики.
  Визуальная переработка панелей требует отдельного прохода с просмотром на вашем экране.
- Расширение памяти эпизодов (`MAX_EPISODES`) и обучение на корпусе большего словаря остаются как были.
- Реальная GGUF-модель и LM Studio в этой среде не проверялись; проверены тесты с фейковой моделью и mock SSE.
