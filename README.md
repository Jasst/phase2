# PulseNet · ТРИПЛЕКСИЯ

Чат с локальной LLM (llama.cpp или LM Studio) и памятью агента.
Память хранит факты с источниками и документы; в промпт попадают только релевантные фрагменты.
Память доступна внешним ИИ по MCP. Локально, один владелец, append-only, без облака.

## Зачем это

Три проблемы LLM-агентов:

1. **Память.** У модели нет долговременной памяти. RAG находит похожие куски, но не «знает факт,
   который я сказал месяц назад».
2. **Забывание.** Дообучение стирает старое. Continual learning — открытая проблема.
3. **Доверие.** Ответ нельзя проверить обратно до источника. Галлюцинации неотличимы от фактов.

PulseNet закрывает всё три в одном слое:

- **память** — append-only журнал фактов `(s, r, o)` с провенансом, документами и гибридным поиском;
- **забывание** — `retract`/`supersede` не удаляют запись; LoRA-«сон» принимается только через гейт отката;
- **доверие** — каждый факт имеет `source.doc_id` + `span` (дословная позиция в тексте) и интервалы времени.

## Статус

Alpha. 87 тестов, `eval/`, `web/`, `server.py`, MCP — есть.
Работает happy path; на реальных русских данных точность не измерена; «Сон» на GPU не проверен.
Код писался с ИИ по архитектурному брифу — это влияет на качество: местами обрезано, местами несогласовано.

Проект — инфраструктура под «память агента», не «осознанный ИИ». Здесь нет self-model, агентного цикла
и планирования. Здесь есть память, на которой это можно строить.

## Запуск

1. `setup_env.bat` — создаёт `.venv` и ставит зависимости.
2. Скопируйте `.env.example` в `.env` и заполните пути, токен MCP и `TRIPLEX_USER_NAME`.
3. `run_server.bat` — поднимает nginx и SearXNG (если Docker запущен) и сервер.
   `stop_server.bat` останавливает контейнеры nginx и SearXNG.
   Откройте `http://127.0.0.1:8000` (старый адрес `/ai` тоже работает).
4. Напишите сообщение в интерфейсе. Модель — через бэкенд из `.env`.

Минимальный `.env`:

    LLM_BACKEND=llamacpp
    LLAMACPP_AUTOSTART=1
    LLAMACPP_DEFAULT_MODEL=Qwen2.5-7B-Instruct-Q4_K_M.gguf
    MODELS_DIR=./models

    TRIPLEX_MEMORY=1
    TRIPLEX_EXTRACT=1
    TRIPLEX_USER_NAME=ВашеИмя
    TRIPLEX_MCP_TOKEN=<длинный случайный токен>

## Как устроена «триплексия»

Три слоя, три оси времени, три операции, три стадии поиска, три этапа «сна».

**Слои памяти**

| Слой | Файл | Что хранит |
|---|---|---|
| Скелет | `journal.py` | Факты `(s, r, o)` с провенансом, confidence, историей |
| Плоть | `docstore.py` | Исходные документы и чанки |
| Индексы | `index.py` | LSH ∪ VectorIndex → RRF |

**Оси времени**

- valid-time: `valid_from` / `valid_to` — когда факт был правдой в мире;
- transaction-time: `recorded_at` / `invalid_at` — когда записали / отозвали;
- access-time: `last_accessed` / `access_count` — когда доставали.

**Операции**

- `assert` — записать факт;
- `retract` — отозвать (запись остаётся);
- `supersede` — вытеснить новым (старый закрывается на `valid_from` нового).

**Стадии поиска**

- coarse: LSH ∪ cosine → RRF;
- expand: BFS по сущностям, глубина ≤ 2, вес пути = Π(confidence × decay);
- rerank: `0.7·cos + 0.3·lex`, expanded умножается на вес пути.

**Этапы «сна»**

- eligible: семантические факты (τ=∞), conf ≥ 0.8, access ≥ 3, возраст ≥ 7 дней;
- rehearsal: 40% датасета — старые факты;
- gate: адаптер принимается только если старые факты просели ≤1% и ppl выросла ≤1%.

## Как работает запись

Сообщение уходит в очередь индексации после ответа. Документ делится на фрагменты, модель извлекает
факты в JSON, факт принимается только если его цитата дословно есть в тексте. Сущности связываются,
отношения приводятся к онтологии, конфликты для `functional` разрешаются. Факт попадает
в `data/triplex/journal.jsonl`. Ошибки видны в блоке «Ошибки» интерфейса и в `/api/status`.

## Как работает поиск

Стартовые кандидаты: LSH и косинус, слияние RRF. Пройдут только релевантные: косинус ≥ `TRIPLEX_MIN_COS`
или половина слов запроса есть в тексте. Граф сущностей расширяется на два шага, вес пути —
произведение уверенности и затухания. Пустой результат → обычный поиск по фрагментам.
Пустой контекст не добавляется в промпт.

Формулы:

- RRF: `score(d) = Σ 1/(60 + rank(d))`;
- затухание: `salience(t) = s₀·e^(−Δt/τ) + 0.1·min(ln(1 + access), 10)`, архив при `< 0.1` (только для конечного τ);
- уверенность: `conf = оценка_модели · 0.8 · множитель_связывания`.

## «Сон» (консолидация в LoRA)

Отбор: семантическое отношение, уверенность ≥ 0.8, обращений ≥ 3, возраст ≥ 7 дней, не вытеснен.
Эпизодические факты не консолидируются.

    python -m pulsenet consolidate                 # датасет, без обучения
    python -m pulsenet train-sleep data/triplex/sleep/<файл>.jsonl \
        --base E:\hf\Qwen --out E:\lora\run1 \
        --llama-cpp C:\llama.cpp --gguf E:\models\lora\triplex-sleep.gguf

Обучение требует GPU, torch, transformers и peft. В песочнице не проверено. Адаптер принимается,
только если ответы на старые факты падают не больше чем на 1%, а перплексия растёт не больше чем на 1%
(`sleep.accept_adapter`). Подключение: `LLAMACPP_EXTRA_ARGS=--lora-scaled <gguf> 0.5`.

## Эмбеддер

Подходит любая модель эмбеддингов, которую можно загрузить в LM Studio или запустить через llama-server.
Модель, размерность и префиксы задач определяются автоматически.

**Вариант 1 — LM Studio (рекомендуется).** Загрузите модель (bge-m3, nomic, e5 и т.д.) и оставьте
загруженной. В `.env` достаточно `TRIPLEX_EMBED_URL=http://localhost:1234/v1`. Приложение находит модель
по имени, измеряет размерность пробным запросом и выбирает префиксы: для nomic `search_document:`/
`search_query:`, для e5 `passage:`/`query:`, для bge-m3 ничего.

**Вариант 2 — отдельный процесс.** Задайте `TRIPLEX_EMBED_MODEL_PATH`. Процесс `llama-server --embedding`
стартует вместе с приложением и грузит модель один раз. Для bge-m3 пулинг `cls`, для nomic `mean`
(`TRIPLEX_EMBED_POOLING`).

Явные `TRIPLEX_EMBED_MODEL` и `TRIPLEX_EMBED_DIM` нужны только если автоопределение ошибается.
Если размерность в `.env` не совпадает с моделью, приложение использует размерность модели
и пишет предупреждение в журнал.

Тексты кэшируются в `data/triplex/embed_cache.jsonl`: при перезапуске известные тексты в модель не уходят.
Смена модели, размерности, пулинга или префиксов создаёт новый кэш. Если эмбеддер недоступен,
приложение переходит на офлайн-хеш, причина попадает в журнал ошибок.

Проверка: `/api/status` → `embedder.name` = `openai+cache`, `embedder.model` = имя модели.
В варианте 2 поле `embedder.server_starts` остаётся 1 между запросами.

Качество на русском зависит от модели. Для русской речи берите многоязычную (bge-m3 или multilingual-e5),
а не только английскую (nomic). Измерить:
`python eval/eval_g2.py --encoder openai --url http://localhost:1234/v1 --dim <размерность>`.

| Инструмент | Что делает |
|---|---|
| `triplex_assert` | записать факт с провенансом |
| `triplex_query` | действующие факты на момент `as_of` |
| `triplex_retract` | отозвать (запись остаётся) |
| `triplex_supersede` | явно вытеснить новым |
| `triplex_ingest` | документ + экстракция фактов |
| `triplex_search` | гибридный поиск + готовый `context` |
| `triplex_define_relation` | онтология: aliases, functional, τ_days |
| `triplex_link_entity` | привязать написание к сущности |
| `triplex_confirm` | подтвердить / опровергнуть факт |
| `triplex_consolidate` | «сон», сухой прогон |
| `triplex_check` | проверка инвариантов I1–I5 |
| `triplex_stats` | счётчики |
| `triplex_whoami` | кто отвечает |

## Инварианты (I1–I10)

| # | Инвариант |
|---|---|
| I1 | Каждый факт имеет `source.doc_id` и валидный `span` |
| I2 | `valid_from ≤ valid_to`, `invalid_at ≥ valid_from` |
| I3 | `retract ⇒ invalid_at задан и retracted=True`, запись остаётся |
| I4 | `supersede ⇒ old.invalid_at == new.valid_from`, цепочка ациклична |
| I5 | У `functional (s,r)` нет двух действующих фактов с разными `o` |
| I6 | Состояние после `replay` детерминировано (`state_hash`) |
| I7 | Повторный `assert` того же факта не создаёт дубликат |
| I8 | Сбой экстракции ⇒ документ сохранён, фактов нет |
| I9 | `confirm`/`deny` меняют только `confidence` |
| I10 | Каждое `access` увеличивает `access_count`, обновляет `last_accessed` |

Проверка: `triplex_check` → пустой список = журнал корректен.

## Сравнение

| Система | Что делает | PulseNet |
|---|---|---|
| RAG (chunks + vector) | похожие куски | + факты, граф, провенанс, время |
| Mem0 | память из диалога | + append-only, инварианты, supersede |
| Zep | temporal KG | + битемпоральность жёстче, LoRA-сон с гейтом |
| GraphRAG | граф + summaries | + онтология, decay |
| Letta/MemGPT | виртуальный контекст | + MCP, local-first, один владелец |
| Cognee | memory layer | + гейт-откат для LoRA |

Ни одна не совмещает append-only + битемпоральность + провенанс + онтологию + гибридный поиск
+ LoRA-сон с гейтом в одном локальном MCP-сервере. Каждый кусок существует отдельно — вместе почти нет.

## Что не сделано

- «Сон» не обучен и не проверен на GPU.
- Режимы B/C (kNN-LM, смещение логитов): нужны скрытые состояния модели.
- Точность на реальных данных не измерена: см. `eval/`.
- Склонения сводятся только вручную (`triplex_link_entity`).
- HNSW и cross-encoder не реализованы: точный поиск и лексическая переранжировка.
- Нет входа в веб-интерфейс: `/api/*` открыт всем, кто достучится до сервера.
- Эпизодическая память (тройка связанных фактов) не реализована — см. ROADMAP.

## Безопасность

`/mcp` закрыт токеном. `/api/*` и `/` без входа. При публичном домене ограничьте их на уровне nginx
(`allow` по IP или `auth_basic`), иначе память и чат доступны всем. См. ROADMAP P0.1.
