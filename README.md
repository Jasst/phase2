# pulsenet · ТРИПЛЕКСИЯ

Чат с локальной LLM (llama-server или LM Studio) и памятью агента. Память хранит факты с источниками
и документы; при ответе в промпт попадают только релевантные фрагменты. Память доступна внешним ИИ по MCP.

## Что внутри

    pulsenet/
      app.py          чат, очередь индексации, журнал ошибок
      server.py       HTTP: веб-интерфейс, API, /mcp
      llm.py          бэкенды llama-server и LM Studio
      triplex/        ядро памяти
        journal.py      журнал фактов: би-темпоральность, инварианты I1–I10, replay
        docstore.py     документы и чанки
        index.py        LSH (512 бит, фикс. seed), косинус, RRF
        encoder.py      эмбеддеры: офлайн-хеш и /v1/embeddings
        extract.py      экстракция: промпт, строгая валидация (цитата обязана быть в тексте)
        memory.py       запись, связывание, поиск в три стадии, затухание и архив
        mcp.py          JSON-RPC, 13 инструментов
        sleep.py        «Сон»: отбор фактов, датасет, гейт, LoRA, конвертация
    web/index.html    интерфейс: чат с Markdown/SSE, сессии в браузере, панель памяти и статуса
    web/static/       app.css, app.js и локальные vendor-библиотеки (marked, DOMPurify, highlight.js)
    eval/             измерение гейтов G2 и G3 (см. eval/README.md)
    tests/            87 тестов

Удалено относительно прежней версии: сеть импульсов (`BrainNet`, `cortex`, `reasoning`, `planner`,
`thoughts`, `imprints`, `chain`, `store`, `vocab`, `config`), её маршруты `/net/*`, старый интерфейс и
CLI-чат. Старый архив сохранён отдельно и не нужен для работы.

## Запуск

1. `setup_env.bat` — создаёт `.venv` и ставит зависимости.
2. Скопируйте `.env.example` в `.env` и заполните пути, токен MCP и `TRIPLEX_USER_NAME`.
3. `run_server.bat` — поднимает nginx (если Docker запущен) и сервер. Откройте `http://127.0.0.1:8000`
   (старый адрес `/ai` тоже работает).
4. В интерфейсе напишите сообщение. Режим — модель через бэкенд из `.env`.

## Как работает запись

Сообщение пользователя уходит в очередь индексации после ответа. Документ делится на фрагменты,
модель извлекает факты в JSON, факт принимается только если его цитата дословно есть в тексте.
Затем сущности связываются, отношения приводятся к онтологии, конфликты для `functional` разрешаются.
Факт попадает в `data/triplex/journal.jsonl`. Ошибки видны в блоке «Ошибки» интерфейса и в `/api/status`.

## Как работает поиск

Перед ответом ищутся факты и фрагменты. Стартовые кандидаты: LSH и косинус, слияние RRF. Пройдут только
релевантные: косинус ≥ `TRIPLEX_MIN_COS` или половина слов запроса есть в тексте. Затем граф сущностей
расширяется на два шага, вес пути = произведение уверенности и затухания. Пустой результат → обычный
поиск по фрагментам. Пустой контекст не добавляется в промпт.

Формулы:
- RRF: `score(d) = Σ 1/(60 + rank(d))`;
- затухание: `salience(t) = s₀·e^(−Δt/τ) + 0.1·min(ln(1 + access), 10)`, архив при `< 0.1` (только для конечного τ);
- уверенность: `conf = оценка_модели · 0.8 · множитель_связывания`.

## «Сон» (консолидация в LoRA)

Отбор: семантическое отношение, уверенность ≥ 0.8, обращений ≥ 3, возраст ≥ 7 дней, не вытеснен.
Эпизодические факты не консолидируются.

    python -m pulsenet consolidate                 # датасет, без обучения
    python -m pulsenet train-sleep data/triplex/sleep/<файл>.jsonl --base E:\hf\Qwen --out E:\lora\run1 \
        --llama-cpp C:\llama.cpp --gguf E:\models\lora\triplex-sleep.gguf

Обучение требует GPU, torch, transformers и peft. В песочнице не проверено. Адаптер принимается, только если
ответы на старые факты падают не больше чем на 1%, а перплексия растёт не больше чем на 1%
(`sleep.accept_adapter`). Подключение: `LLAMACPP_EXTRA_ARGS=--lora-scaled <gguf> 0.5`.

## Эмбеддер

Подходит любая модель эмбеддингов, которую можно загрузить в LM Studio или запустить через llama-server.
Модель, размерность и префиксы задач определяются автоматически.

**Вариант 1 — LM Studio (рекомендуется).** Загрузите модель эмбеддингов в LM Studio (bge-m3, nomic, e5 и т.д.)
и оставьте её загруженной. В `.env` достаточно `TRIPLEX_EMBED_URL=http://localhost:1234/v1`.
Приложение находит модель по имени в списке моделей сервера, измеряет размерность одним пробным запросом
и выбирает префиксы: для nomic `search_document:` и `search_query:`, для e5 `passage:` и `query:`, для bge-m3 ничего.

**Вариант 2 — отдельный процесс.** Задайте `TRIPLEX_EMBED_MODEL_PATH`. Процесс `llama-server --embedding` стартует
вместе с приложением и грузит модель один раз. Для bge-m3 пулинг `cls`, для nomic `mean` (`TRIPLEX_EMBED_POOLING`).

Явные `TRIPLEX_EMBED_MODEL` и `TRIPLEX_EMBED_DIM` нужны только если автоопределение ошибается. Если размерность
в `.env` не совпадает с моделью, приложение использует размерность модели и пишет предупреждение в журнал.

Тексты кэшируются в `data/triplex/embed_cache.jsonl`: при перезапуске известные тексты в модель не уходят.
Смена модели, размерности, пулинга или префиксов создаёт новый кэш. Если эмбеддер недоступен, приложение
переходит на офлайн-хеш, а причина попадает в журнал ошибок.

Проверка: `/api/status` → `embedder.name` = `openai+cache`, `embedder.model` = имя модели.
В варианте 2 поле `embedder.server_starts` остаётся 1 между запросами.

Качество на русском зависит от модели. Для русской речи берите многоязычную (bge-m3 или multilingual-e5),
а не только английскую (nomic). Измерить: `python eval/eval_g2.py --encoder openai --url http://localhost:1234/v1 --dim <размерность>`.

## Что не сделано

- Модуль «Сна» не обучен и не проверен на GPU.
- Режимы B/C (kNN-LM, смещение логитов): нужны скрытые состояния модели.
- Точность на реальных данных не измерена: см. `eval/`.
- Склонения сводятся только вручную (`triplex_link_entity`).
- HNSW и cross-encoder не реализованы: точный поиск и лексическая переранжировка.
- Нет входа в веб-интерфейс: `/api/*` открыт всем, кто достучится до сервера.

## Безопасность

`/mcp` закрыт токеном. `/api/*` и `/` без входа. При публичном домене ограничьте их на уровне nginx
(`allow` по IP или `auth_basic`), иначе память и чат доступны всем.
