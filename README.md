# Brain Chat — исправленная версия

## Файлы
- `brain_chat.py` — графовая сеть, обучение на тексте, pygame-интерфейс, команды чата.
- `mind.py` — ассоциативный поток и генерация кандидатов.
- `lm_backend.py` — подключение llama-cpp-python или LM Studio и фоновая очередь.

## Что исправлено
1. Обучение создаёт связи между всеми парами слов в пределах `TRAIN_WINDOW`, а не только между соседними словами. Направленные биграммы при этом остаются только для соседних слов.
2. Устранено ложное обучение биграмм на стыке двух независимых пользовательских сообщений.
3. Сгенерированные самой сетью последовательности больше не укрепляют автоматически собственные биграммы и связи.
4. Несколько кандидатов ответа генерируются из одинакового состояния `Mind`, чтобы предыдущий кандидат не влиял на следующий.
5. Непроверенный ответ больше не закрепляется автоматически. Обучение по ответу происходит после `/good` или `/teach`.
6. Частота биграмм в оценке кандидата использует `log1p`, чтобы большие счётчики не подавляли остальные признаки.
7. Замедлено глобальное затухание связей во время фоновой симуляции.
8. Сохранение стало атомарным и создаёт каталог; чтение поддерживает отсутствие необязательных полей.
9. Добавлена обработка UTF-8 BOM при обучении из файла.
10. LM backend улучшен: обработка ошибок HTTP, content-массивов, настройки через переменные окружения, безопасное обновление истории только для актуального запроса.
11. `/good` связывает подтверждённый ответ с последним вопросом и перестраивает группы.

## Запуск
Установить pygame:

```bash
python -m pip install pygame
```

Для прямой загрузки GGUF дополнительно установить `llama-cpp-python` с подходящей сборкой под CPU/CUDA:

```bash
python -m pip install llama-cpp-python
```

Затем указать путь к модели в `lm_backend.py` или через переменные окружения.

Для LM Studio в Windows PowerShell:

```powershell
$env:BRAIN_LM_BACKEND="lmstudio"
$env:BRAIN_LM_URL="http://localhost:1234/v1/chat/completions"
$env:BRAIN_LM_NAME="имя-загруженной-модели-в-LM-Studio"
python brain_chat.py
```

Для llama.cpp:

```powershell
$env:BRAIN_LM_BACKEND="llamacpp"
$env:BRAIN_LM_PATH="D:\models\model.gguf"
python brain_chat.py
```

## Команды чата
- `/save` — сохранить состояние.
- `/load` — загрузить состояние.
- `/reset` — создать новую сеть в памяти.
- `/train путь_к_файлу.txt` — обучить на текстовом файле.
- `/teach правильный ответ` — явно обучить на правильном ответе после вопроса.
- `/good` — подтвердить последний ответ и закрепить связь вопрос→ответ.
- `/bad` — ослабить цепочку последнего ответа.
- `/groups`, `/mind`, `/sleep`, `/temp N`, `/conf N` — диагностика и настройки.

## Важное ограничение архитектуры
Это экспериментальная графовая ассоциативная система: нейроны-узлы, веса связей, статистика биграмм, группировка и динамика активаций. Она **не** является полноценной обучаемой языковой нейросетью уровня Transformer и не использует backpropagation/градиентный спуск. LM-модель (GGUF или LM Studio) отдельно формулирует связный текст; графовая сеть предоставляет ассоциации и контекст. Оценка `conf` — ассоциативное сходство кандидата с контекстом, а не вероятность истинности.

## Проверки
Проверена синтаксическая компиляция всех трёх Python-файлов. Проведён smoke-test создания графа, обучения, сохранения/загрузки, генерации кандидатов и фоновой очереди LM на тестовом backend. Полный GUI-запуск и подключение к реальной GGUF/LM Studio модели в этой среде не проверялись.

## Обучение через LLM и легенда групп (v14)
- Правый клик по слову → «обучить через LLM»: LLM объясняет слово, сеть создаёт
  исходящие связи от слова и от слоёв объяснения, дистиллирует знание в ансамбль.
- F3 — легенда всех групп нейронов (включая одиночные).
- Оценка сетей при адаптации — LLM-судья (0–10); без LLM — совпадение слов.

## Цепочка сетей (v13, папка nets/)
Ответ теперь может формироваться цепочкой из нескольких сетей: выход одной
становится входом следующей, пока мысль не стабилизируется. Сети строятся из
текстов проекта и дообучаются по `/good` и `/teach` через изолированную песочницу.

- `/chain` — трасса последнего ответа по раундам.
- `/nets` — состояние сетей, очереди адаптаций и результат последней адаптации.
- Файлы сетей, опыта и логов — в `nets/_store/`, `nets/_logs/`, `nets/_sandbox/`.
- Подробности и ограничения: `nets/README.md`, `CHANGES_v13.md`.
